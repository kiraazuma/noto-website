# スマホKinetic INDEXの能登の見切れ

スマホの静止状態Iは字形高さの3%、途中状態E1は6%だけ上端を見切れさせる。P.noto.wordIt/wordIbは実際の「能登」をCanvasで測定したink bounds。既存の配置計算用の共有it/ibは維持し、`inkTop = -(crop * (wordIb - wordIt) + wordIt - it) * size`でat()の基準へ変換する。

文字サイズG/G1と横位置は維持。登場時のtrack/easing、PC配置、詳細配置、HERO、写真マスク処理は変更していない。中央3語と右側情報は既存のnb/at0計算で新しい位置に追従する。

| 表示領域 | 上端の見切れ | 字形高さに対する割合 |
|---|---:|---:|
|375×667|5.41px|2.98%|
|390×664|5.62px|2.97%|
|390×844|5.62px|2.97%|
|430×932|6.23px|2.98%|

transformの0.1px丸めにより3%からわずかに差が出る。短い表示領域でも上段と中央情報の間は31px以上、中央情報と朝市の間は35px以上を確保。進行度0.40/0.60/0.75/0.84で見切れは約5.99/4.61/3.15/2.97%。664→844→664のリサイズ後に配置が一致。写真ホバー回帰チェック392項目、構文チェック、git diff --checkが通過。

検証ページ: `/tools/mobile-index-check.html?width=390&height=664`。resizeを付けると高さを180px増やして戻す。progress=0.4などを付けると実際のKineticモジュールを独立した進行度で駆動し登場途中を確認する。通常の画面スクロール入力を再現するテストではない。

環境はアプリ内Chromium。Safariアドレスバー表示時に相当する664/667pxの表示領域を確認したが、iPhone Safari実機のブラウザUI・DPR・セーフエリアは未検証。
